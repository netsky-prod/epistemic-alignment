# UC-001: Import health data into the product

Scope: Health-data import system
Level: user-goal
Primary actor: Product/data stakeholder

Stakeholder interests:
- Product stakeholder: import health data with a trustworthy, reviewable outcome.
- Policy/data-governance owner: retain and delete imported data according to an explicitly approved policy.
- Privacy/security reviewers: protect sensitive data and preserve required audit evidence.

Preconditions: An authorized source and applicable import/retention policy are available; exact source and policy details are currently unresolved.
Minimal guarantee: No unapproved durable health-data retention is introduced; unresolved policy is surfaced to the actor with a recoverable next step.
Success guarantee: Valid, authorized health data is imported and its storage/deletion behavior is traceable to a confirmed retention policy.
Trigger: Product stakeholder requests an import.

## Main success scenario
1. Product/data stakeholder submits an authorized health-data source for import.
2. System validates the source and authorization against confirmed rules.
3. System records accepted health data with policy-linked retention metadata.
4. System reports the import outcome and audit reference to the stakeholder.

## Extensions
- 2a. Source is invalid or unauthorized: system rejects the affected input, explains the recoverable error, and leaves existing data unchanged.
- 3a. **Retention policy is unknown (UQ-001):** system does not claim a durable storage/deletion outcome, surfaces the missing policy decision and owner, and pauses the import for human review.
- 3b. Retention policy conflicts with source or consent constraints: system pauses the import and requests policy/privacy review.

Business rules: ASM-001–ASM-003 are proposed; UQ-001–UQ-003 must be answered by their owners before implementation planning. No generic or existing retention period is applicable by inference.
Frequency: Unknown; product/data owner to estimate.
Open issues: UQ-001, UQ-002, UQ-003; INFER-001.
