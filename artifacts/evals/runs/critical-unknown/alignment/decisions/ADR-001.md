# ADR-001: Require explicit retention policy before durable persistence

Status: proposed

Context: Health-data import is requested, but retention is explicitly unknown (UQ-001; STMT-002). Persisting without an owner-approved duration, deletion trigger, exceptions, and audit lifecycle would create an unsupported and potentially unsafe requirement. The policy/data-governance owner will decide later (STMT-003).

Decision: Proposed guardrail for review: the import flow must pause before durable health-data persistence when no confirmed retention policy is available, surface UQ-001 and its owner, and resume only after a human policy decision is recorded. This ADR does not make the retention decision and does not authorize handoff.

Consequences: The unresolved state is visible and recoverable; implementation planning cannot claim retention behavior yet. Import latency and temporary handling need later definition. Once UQ-001 is answered, policy linkage, deletion, exceptions, and audit behavior must be revisited. This is a proposal, not a machine certificate.

Alternatives: Reuse a generic/default retention period (rejected as unsupported); persist indefinitely (rejected as unsafe and unapproved); discard all input without a review path (rejected because it loses a recoverable stakeholder outcome).
