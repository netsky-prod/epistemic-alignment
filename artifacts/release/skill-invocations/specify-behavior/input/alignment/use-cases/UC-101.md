# UC-101 — Request an expedited refund

## Scope and level

- Scope: expedited refund service
- Level: user goal

## Actors

- Primary: eligible customer
- Supporting: support lead, policy owner

## Preconditions

- Eligibility is known.
- The purchase has a stable purchase reference.

## Guarantees

- Minimal: an unaccepted request does not produce a refund-acceptance receipt.
- Success: an eligible request receives a receipt with a stable refund request ID.

## Trigger

The customer submits an expedited refund request for the purchase.

## Main success scenario

1. The customer submits an eligible purchase reference.
2. The service accepts the request.
3. The customer receives a receipt containing a stable refund request ID.

## Extensions

- 1a. The same request was already accepted: return the same receipt and do not create a second refund.
- 2a. The request is ineligible: return the policy reason and a human-review path. This criterion is proposed under ASM-102.

## Acceptance criteria supplied to the behavior stage

- **Confirmed:** An eligible request produces an acceptance receipt with a stable request ID.
- **Confirmed:** Repeating the same request returns the same receipt and does not create a second refund.
- **Proposed:** An ineligible request returns a reason and human-review path.
