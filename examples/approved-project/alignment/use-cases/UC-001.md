# UC-001 — Approve an unchanged release handoff

## Scope and level

- Scope: release-alignment workflow
- Level: user goal

## Actors

- Primary: release sponsor
- Supporting: release manager, delivery engineer, service operator, Codex agent

## Stakeholder interests

- Sponsor: decides from an accurate review.
- Delivery engineer: receives stable planning context.
- Operator: sees risk and responsibility rather than a false certificate.

## Preconditions

- The dossier, semantic review, and local Site exist.
- The Site displays the current included-file digest.

## Guarantees

- Minimal: no handoff exists without a current valid human approval.
- Success: the generated handoff carries the same digest that was issued, rendered, explicitly approved, and rechecked.

## Trigger

The release manager presents the review location, findings, and exact digest to the sponsor.

## Main success scenario

1. The agent snapshots the included dossier files.
2. The Site presents goals, behavior, architecture, risk, findings, and the exact digest.
3. The helper issues that digest as presented.
4. The sponsor explicitly approves that digest in the current interaction.
5. The agent transcribes the decision with `human-message` provenance.
6. The helper verifies the dossier is unchanged.
7. The helper writes `handoff.md` with the verified digest.
8. Superpowers brainstorming consumes the handoff and dossier.

## Extensions

- 4a. Sponsor requests changes: return to the relevant authoring phase; no handoff.
- 4b. Sponsor rejects: close the attempt; no handoff.
- 6a. Included file changed: report stale approval, rebuild, and request a fresh decision.
- 8a. Superpowers unavailable: preserve the verified handoff and report delivery pending.

## Business rules

- BR-001: Agents cannot approve their own work.
- BR-002: Publication requires separate explicit consent.
- BR-003: Semantic findings are for human judgment, not helper certification.

## Frequency

Once per review iteration.
